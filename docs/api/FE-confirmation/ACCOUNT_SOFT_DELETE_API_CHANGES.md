# 帳號軟刪除權限更新

日期：2026-11-24。分支：`fix/deletion-history-safety`，尚未部署。不需新增資料庫 migration。

## API 與權限

沿用 `DELETE /api/admin/account/{id}`，帶現有 bearer token，無 request body。

| 操作者 | 刪除賣家 | 刪除自己所屬賣家的員工 | 刪除其他賣家的員工 | 刪除管理員 |
| --- | --- | --- | --- | --- |
| 平台管理員 | 可 | 可 | 可，包含未分配賣家的員工 | 不可 |
| 賣家本人 | 不可，包含刪除自己 | 可 | 不可 | 不可 |
| 員工 | 不可 | 不可 | 不可 | 不可 |

賣家是否擁有員工，由 DB 的員工群組 parentId 判斷，不信任 FE 傳入的歸屬。平台管理員可刪除尚未完成 onboarding 或已停用的賣家帳號；操作人自身仍須為可用帳號。

## 成功與重試

成功為 HTTP 200，`{success:true,data:Account}`；以下為回應部分欄位：

```json
{
  "success": true,
  "data": {
    "id": "TARGET_ACCOUNT_UUID",
    "role": "seller",
    "status": "inactive",
    "deletedAt": "2026-11-24T12:00:00.000Z",
    "deletedByAccountId": "ACTOR_ACCOUNT_UUID"
  }
}
```

密碼及 credentialVersion 不回傳。重複刪除同一帳號成功回原本刪除時間／操作人，不覆蓋資訊或新增重複活動紀錄。不存在 ID 回 404；權限不足／操作人不可用回 403；管理員目標受保護，回 409。

## 刪除賣家後的員工與資料

- 只將目標帳號設定為 inactive、寫入 deletedAt 及 deletedByAccountId，不實體刪除帳號，不釋放原 email 給新註冊。
- 刪除員工會撤銷該員工 session。刪除賣家會撤銷賣家及其員工 session；舊 access／refresh token 不再可用。
- 員工列本身不會因此被軟刪除，群組歸屬與歷史也保留；只要母賣家為已刪除／停用，員工便不可登入、建立／更新登入 session 或使用已登入 API。此類父帳號不可用情況可回 403 `ACCOUNT_PARENT_UNAVAILABLE`。因 session 已撤銷而被拒絕的 refresh 也可能回既有 `REFRESH_TOKEN_INVALID`。
- 商品、廣告、訂單、退款、錢包、交易及其他歷史記錄保留。此 API 不另外改商品／廣告狀態、不自動退款、回收或搬移餘額；店鋪曝光及資金結算若需其他政策，應另行實作或執行原有管理操作。
- 帳號清單維持排除 deletedAt 非 null 的帳號。沒有提供恢復已刪除帳號 API；僅把 status 改回 active 並不清除 deletedAt，也不恢復登入。

## FE 調整

- 管理員的賣家／員工列都可提供「刪除」操作，管理員列不提供。
- 賣家只可對自己的員工列顯示刪除，不提供刪除自己或其他賣家的功能。員工不可顯示刪除操作。
- 刪除賣家時確認文案應說明「賣家及其員工將失去登入／使用權限，歷史資料與餘額保留」，不要宣稱員工／商品／訂單會一起刪除。
- 成功後刷新帳號清單。403／409 按伺服器結果顯示，不能只依 FE 的按鈕可見性保護權限。
- 遇帳號或母賣家不可用，停止原帳號後續操作，清理本機登入狀態並引導重新登入。

## 驗證

回歸測試包含：管理員刪除賣家／員工／未分配員工、賣家刪除本人員工、拒絕跨賣家／員工操作／賣家自行刪除、保護管理員、重試不重複紀錄、撤銷登入及 refresh、母賣家停用時阻擋員工，以及保留商品／訂單／錢包／交易內容。所有資料寫入測試皆使用 disposable DB，不對共享環境刪除真實帳號。
