# 商品刪除 API 修正通知（Admin FE）

日期：2026-11-16

狀態：後端程式已完成，Build 與 API 整合測試通過；尚未部署，需待目標環境部署後驗收。

## 本次變更

商品不允許永久刪除。平台管理員可以軟刪除，賣家僅能透過商品更新 API 下架自己的商品。

| 操作 | API | 最新行為 |
| --- | --- | --- |
| 永久刪除 | `DELETE /api/admin/product/:id/permanent` | **路由已完全移除**，所有角色呼叫舊路徑均回傳 `404`。 |
| 軟刪除 | `DELETE /api/admin/product/:id` | 僅平台管理員（`admin`）可操作；賣家及員工回傳 `403`。 |
| 下架 | `PUT /api/admin/product/:id`，body 為 `{ "status": "inactive" }` | 保留既有商品更新權限；賣家可下架自己的商品。 |

先前文件所述永久刪除回傳 `410 PRODUCT_PERMANENT_DELETE_DISABLED` 已被本次變更取代。該路由與 Swagger 定義均已移除，沒有替代的永久刪除 API。未匹配路由的 `404` 不保證為 JSON，請勿直接假設回應包含 `success` 或 `code`。

## FE 需要調整

1. 所有角色的商品頁面移除「永久刪除」按鈕、確認視窗及 API 呼叫。
2. 「刪除商品」僅對平台管理員顯示，呼叫軟刪除 API；不可只因使用者能登入管理後台就顯示。
3. 賣家使用「下架」操作，呼叫商品更新 API，不要呼叫任何商品 DELETE API。
4. 軟刪除成功後重新整理商品列表；預設列表不包含已軟刪除商品。
5. 不提供「恢復已刪除商品」或「重新上架已刪除商品」操作，目前沒有恢復 API。

建議軟刪除確認文案：

> 刪除後，商品及所有規格將下架，相關未封存廣告將暫停，並從買家的購物車與收藏移除。歷史資料會保留，目前無法透過系統恢復。確定刪除？

## 軟刪除 API

```http
DELETE /api/admin/product/PRODUCT_UUID
Authorization: Bearer ADMIN_ACCESS_TOKEN
```

不需要 request body。成功維持既有 `{ "success": true, "data": ... }` 格式，`data` 為商品資料，包含 `status: "inactive"`、非空的 `deletedAt` 與 `deletedByAccountId`。

| HTTP 狀態 | 意義 |
| --- | --- |
| `200` | 軟刪除成功；管理員重複刪除同一商品也可成功。 |
| `400` | 商品 ID 格式不符等請求驗證錯誤。 |
| `401` | 未登入或憑證無效。 |
| `403` | 非平台管理員，包含商品所屬賣家與員工。 |
| `404` | 商品不存在。 |

軟刪除會保留商品、規格及歷史業務資料，將商品與所有規格設為 `inactive`、暫停未封存廣告，並移除該商品的購物車及收藏項目。它不會執行商品資料列的永久刪除。

已軟刪除商品不能透過一般更新 API 恢復或修改，會回傳 `409`。下架與軟刪除不同：未軟刪除商品仍可依既有規則重新上架。若另外建立同名商品，會取得新的商品 ID，舊訂單、退款及廣告紀錄不會轉移。

## FE 驗收項目

- 平台管理員可軟刪除商品；成功後一般商品列表不再顯示該商品。
- 賣家及員工不顯示刪除操作；直接呼叫軟刪除 API 回傳 `403`，商品維持原狀。
- 賣家仍可下架自己的商品。
- 舊永久刪除路徑回傳 `404`，商品及歷史資料仍保留。
- 已軟刪除商品不提供編輯或恢復操作。

## Flutter 影響

本次沒有修改 Flutter/App API 的路徑、請求或回應格式。商品下架或軟刪除後，App 重新取得商品／廣告清單時會依既有可見性規則反映狀態；已載入的畫面需重新整理。
