# 賣家收益與廣告管理｜定案摘要

截至日期：2026 年 11 月 17 日。本文彙整第一版最終業務規則，供團隊確認與交接。

目前已合併至 development，完成 local 與 dev 資料庫遷移及結構核對；dev 服務尚待部署新版本。買家 App 操作與 API 合約維持不變。參數與串接細節見 [FE 文件](../api/FE-confirmation/SELLER_EARNINGS_AND_AD_AUTOMATION.md)。

## 一、兩個錢包與收益顯示

| 項目 | 規則 |
| --- | --- |
| 廣告錢包 | 保留現有錢包，供廣告儲值使用；賣家可申請現金入金、出金。 |
| 收益錢包 | 獨立記錄商品收益，分為現金與金幣餘額；賣家只可申請提領，兩個錢包不互轉。 |
| 累計／期間商品收益 | 銷售減已完成商品退款，尚未扣抽成；不含運費、廣告入金、人工調整或提領。金幣以枚顯示。 |
| 目前餘額 | 扣除抽成、退款、費用、已完成提領及欠款抵扣後，留在收益錢包的淨額。 |
| 待開放提領 | 尚未通過保留期或每日開放作業的剩餘淨收益。 |
| 可提現金額 | 已開放且未保留給其他申請的可提金額；不是全部收益餘額，也不代表立即匯款。 |
| 待抵扣款項 | 扣款超過可抵扣收益的欠款；有欠款不得新提領，無欠款時隱藏。 |

付款確認及退款完成時即時更新。支援累計、一週、一個月及自訂期間，起訖時間由前端選定；期間篩選不改變目前餘額。退款記在完成退款的期間，不回溯修改原銷售期間。保留各筆收支、申請與處理紀錄。

每 10 枚金幣折合 1 元。餘額核對方式：**現金餘額＋金幣餘額 ÷ 10＝待開放＋已開放餘額**。沒有欠款時，已開放餘額由可申請金額、提領保留款及尾數組成；欠款另外列示，不重複扣除。

## 二、抽成與運費

| 項目 | 負擔方式 |
| --- | --- |
| 平台抽成 | 商品收益收取 10%，按原交易現金／金幣比例分攤；提領不再抽成。商品退款按比例退回抽成。 |
| 抽成排除 | 運費、買家交易附加費、額外退款補償及人工調整。 |
| 買家交易附加費 | 歸平台抵銷金流成本；第一版維持 0%，金流及額外金流退款費由平台負擔。 |
| 超商配送 | 平台支付標準物流費；標準費與買家實付運費的差額由賣家負擔，同一配送不按商品件數重複收費。 |
| 宅配 | 買家支付的宅配運費歸賣家，賣家自行支付物流業者；平台不再扣標準宅配成本。 |
| 虛擬商品 | 無運費適用；資料核對一致後不顯示運費待確認。 |
| 退貨寄回運費 | 賣家負擔、平台先代墊；管理員核對實際總額及已收費紀錄後，另行手動調減收益。不固定計費、不自動扣款、不增加買家退款。 |

超商配送費已發生時，退款或未取貨不退回賣家補貼；僅整筆配送取消且管理員確認沒有物流費，才能退回一次。不能只憑取消狀態判定免費。

例：商品 1,000 元，超商標準運費 69 元、買家付 30 元，賣家淨收益為 **1,000 − 100 抽成 − 39 補貼＝861 元**。

## 三、收益開放與平台資金

**確認付款 → 即時記錄收益及費用 → 優先抵欠款 → 剩餘列待開放 → 滿保留期後每日開放 → 賣家申請 → 管理員付款。**

- 所有確認付款的銷售均納入，不以送達或退款期限結束為條件。
- 正式／staging 保留 14 天（336 小時）；dev／local 為十分之一，即 33 小時 36 分鐘。
- 每日臺北時間 03:00 開放已滿保留期的剩餘款項。正常等待時間正式環境為 14 至未滿 15 天，dev／local 為 33 小時 36 分鐘至未滿 57 小時 36 分鐘。
- 開放只改變可領狀態，不重複入帳；作業延遲時補處理到期款項。買家退款期限不受影響。
- 不另提列固定比例退款準備金。平台接受退款墊付風險；保留期不保證綠界已撥款。
- 平台資金不足時暫緩實際付款，收益、開放及申請照常，申請留待處理並顯示說明，資金到位後繼續。

## 四、退款、原運費退還與欠款

商品退款完成時，扣回賣家對應淨收益並退回抽成；額外退款由賣家全額負擔。尚未完成的退款不保留收益、不阻止開放或提領。

原運費退還分為「退還原運費」勾選及「其他額外補償」輸入，合計為額外退款。同一原始配送的運費只能退一次，跨商品或分次退款皆適用。退款清單與明細顯示買家實付運費，以及可退、其他退款占用、已退、不適用或待核對狀態。選取時占用資格，取消／拒絕釋放，完成後不可再次退還；此資格占用不凍結收益。

商品退款先抵原交易剩餘收益，不足再抵其他已開放、其他待開放收益；其他收益各組先現金後金幣，仍不足列欠款。運費補貼及額外退款先扣現金、不足再扣金幣折現。後續淨收益優先清償欠款，餘額再按保留期處理。

退款或人工扣款使待處理提領的金幣／現金組合不足時，取消受影響申請並說明，讓賣家重新申請。已開始對外付款的保留款不得挪用；不足另列欠款，已進行的付款仍如實完成扣帳。

## 五、賣家申請與管理員處理

| 作業 | 流程與限制 |
| --- | --- |
| 廣告錢包入金 | 賣家申請 → 管理員自行確認銀行收款 → 完成入帳。提出申請不增加餘額。 |
| 廣告錢包／收益錢包提領 | 賣家申請並保留款項 → 管理員開始付款 → 確認付款完成並扣帳。收益提領由賣家指定現金與金幣組合。 |
| 審核金額 | 管理員只能維持或減少，現金與金幣各自受限，不能互換或增加；保留原始、最終金額及原因。全數不核准則拒絕。 |
| 取消／拒絕 | 賣家只能取消自己的待處理申請；管理員可拒絕待處理申請。釋放未使用保留款。 |
| 付款處理中 | 不再改金額、取消或拒絕；實際付款不明時先核對，不任意釋放保留款。 |
| 提領單位 | 現金整元、金幣 10 枚倍數，合計大於零；尾數分別留存，不合併湊整元。廣告錢包入金最多兩位小數。 |

一般入出金由賣家發起，管理員不得代為建立。第一版不串銀行、不做多層簽核，管理員自行確認銀行收付款；申請頁顯示狀態與說明。

管理員可另作**收益帳務調整**，明確填寫現金／金幣增減額及原因，用於退貨運費或更正；不是銀行存提，不改商品歷史收益、不收抽成。增加先抵欠款，剩餘立即開放；減少先扣指定幣別已開放、再扣待開放，不足按既定跨幣別及欠款規則處理。保留歷史紀錄，重送不得重複入扣帳。

## 六、廣告批次操作與自動補款

資金僅來自廣告錢包可用餘額，不動用收益錢包或提領保留款。每則廣告保留交易紀錄，可查累計及指定期間儲值、觀看消耗；儲值不含廣告間轉入或返還款。

| 功能 | 規則 |
| --- | --- |
| 批次補款 | 同一賣家的多則廣告，可各設金額或填相同金額；整批成功或整批不扣款，失敗顯示原因。 |
| 批次啟用／暫停 | 逐則回報結果，遵守既有資格限制。 |
| 自動補款設定 | 僅開關及每次固定金額；預設關閉，金額預設 500 元、最低 100 元，無每日上限。 |
| 門檻 | 廣告餘額低於 100 元才補固定金額；例如剩 80 元、補 500 元後為 580 元。 |
| 觸發時機 | 觀看扣款完成、廣告錢包入金完成、開啟或修改設定時檢查；服務恢復補處理待辦。不使用每分鐘排程，也不在分配廣告或開寶箱時觸發。 |
| 資金不足 | 不部分補款、不透支；多則等待時優先最早等待者。 |
| 不適用狀態 | 手動暫停、封存、已結清、商品下架／軟刪除、無可售規格或賣家停用時不補款。 |

每次補款保留錢包扣款及廣告入帳紀錄，納入儲值統計；重複事件不重複補款。

## 七、啟用範圍與延後項目

只納入設定起算時間後確認付款、且由新流程記帳的交易；不自動回補歷史銷售，未入帳舊銷售的退款不扣新收益錢包。報表標示起算範圍，正式啟用時間於部署時確認。

第一版不含銀行串接、兩錢包互轉、歷史收益匯入、停止銷售後的催收／核銷、獨立退貨運費報銷及主動通知。非零買家交易附加費須先確認退款政策才啟用。

## 附錄：新增後台 API

以下 11 支路由共同前綴為 `/api/admin`。管理員查詢收益摘要、歷史與申請列表須指定賣家；賣家只能操作自己的資料，一般員工不支援這些新功能。完整參數見 [FE 串接文件](../api/FE-confirmation/SELLER_EARNINGS_AND_AD_AUTOMATION.md)。

| 方法 | 路徑（省略共同前綴） | 用途 | 權限 |
| --- | --- | --- | --- |
| GET | `/seller-earnings/summary` | 目前餘額、期間收益、待開放、可提領與欠款 | 管理員／賣家本人 |
| GET | `/seller-earnings/transactions` | 收益交易歷史 | 管理員／賣家本人 |
| GET | `/seller-earnings/requests` | 入出金申請及審核歷史 | 管理員／賣家本人 |
| POST | `/seller-earnings/requests` | 提出入金／提領申請 | 僅賣家 |
| PATCH | `/seller-earnings/requests/:id` | 審核申請；賣家可取消自己的待處理申請 | 管理員／受限的賣家操作 |
| POST | `/seller-earnings/:sellerId/adjustments` | 人工增減收益 | 僅管理員 |
| POST | `/seller-earnings/:sellerId/shipping-subsidy-reversals` | 核實零物流費後退回超商補貼 | 僅管理員 |
| POST | `/advertisement/batch/budget` | 批次補款 | 管理員／所屬賣家 |
| PATCH | `/advertisement/batch/status` | 批次啟用／暫停 | 管理員／所屬賣家 |
| GET | `/advertisement/:id/auto-refill` | 查詢自動補款設定 | 管理員／所屬賣家 |
| PUT | `/advertisement/:id/auto-refill` | 設定自動補款 | 管理員／所屬賣家 |

既有退款 API 新增運費退還資訊與拆分輸入，廣告統計 API 新增累計／期間儲值欄位；這些不是新增路由。舊管理員直接入金 API 已停用，一般入金改走賣家申請及管理員確認流程。Flutter API 合約不變。
